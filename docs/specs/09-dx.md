## 15. Developer experience and agentic development

Goal: fast feedback, short output (fewer tokens) and rules enforced by machines instead of remembered.

### 15.1 Requirements

- **REQ-DX-001 (MUST)** `pnpm check` runs typecheck (`tsc --noEmit`), `biome check` and the unit tests. It prints only failures and a one-line summary. Exit code ≠ 0 on any failure.
- **REQ-DX-002 (MUST)** `pnpm test <pattern>` runs one test or file; `pnpm test:watch` exists for human use.
- **REQ-DX-003 (MUST)** Vitest uses `unplugin-swc` to emit decorator metadata. The scaffold includes a smoke test that builds a `Test.createTestingModule` and injects a provider through the constructor; nothing else proceeds until it passes. The full unit and contract suites must run in under 30 s locally; if they exceed that, record it in section 14.
- **REQ-DX-004 (MUST)** Biome is the only linter/formatter. Enable the floating-promise rule (`noFloatingPromises`) if the adopted version offers it; otherwise it becomes a review item for `/code-review`. Known pitfall: Biome's `useImportType` rule (and TS `verbatimModuleSyntax`) can turn constructor-injected imports into `import type`, which erases the runtime token Nest DI needs. Keep `emitDecoratorMetadata` and `experimentalDecorators` on, leave `verbatimModuleSyntax` off, and disable `useImportType` if it rewrites injected imports; the DX-003 smoke test must catch this.
- **REQ-DX-005 (MUST)** `pnpm req <ID|prefix>` prints the requirement text and its acceptance block, reading `docs/specs/*.md`. E.g. `pnpm req REQ-ALR-012`, `pnpm req REQ-ALR`.
- **REQ-DX-006 (MUST)** `pnpm req:check` lists MUST requirements with no test citing the ID (searches `test/` and `src/**/*.spec.ts`), ignoring reserved IDs. Informational by default; exits ≠ 0 with `--strict`.
- **REQ-DX-007 (MUST)** `lefthook`: on `pre-commit`, `biome check` on staged files and `tsc --noEmit`; on `commit-msg`, the message must cite a `REQ-*` or start with `chore|docs|build|test|refactor|style:`.
- **REQ-DX-008 (MUST)** Versioned `.claude/settings.json`: `PostToolUse` hook that formats edited `.ts` files; `Stop` hook that runs `pnpm check` and returns only failures; `allow` permissions for `pnpm check|test|req|req:check` and read-only git commands. Hooks are no-ops until the scaffold provides `package.json` and Biome.
- **REQ-DX-009 (SHOULD)** `PW_FETCH_FIXTURES_DIR` (development only; documented in section 6.1, commented out in `.env.example`): `HttpFetcher` answers from `manifest.json` files instead of using the network. Allows running the whole app, with ticker and alerts, offline.
- **REQ-DX-010 (SHOULD)** `pnpm dev:seed` creates a sample product with fixture listings and a rule, on a local development `file:` database.
- **REQ-DX-011 (MUST)** `.env.example` and `docker-compose.yml` work with no edits beyond secrets (REQ-CNT-010).
- **REQ-DX-012 (MUST)** The Node version is pinned in `mise.toml` (`node = "24"`) and in `engines` of `package.json` (`>=24`), with `packageManager` pointing to pnpm. The current dev machine has Node 20: run `mise use node@24` before the scaffold.
- **REQ-DX-017 (MUST)** `package.json` script contract, so every session finds the same commands: `build`, `start` (runs `pricewatch serve`), `check`, `test`, `test:watch`, `test:live`, `req`, `req:check`, `fixtures:capture`, `dev:seed`, `db:generate` (drizzle-kit), plus a `bin` entry `pricewatch`. `prepare` installs lefthook. `check` and `test` use terse reporters (REQ-DX-014).
- **REQ-DX-018 (MUST)** `docs/PROGRESS.md` is the cross-session handoff: current build step (15.2), what is done, the next action, and open blockers. Update it at the end of every slice, so a new session reads it instead of exploring the repo.
- **REQ-DX-013 (MUST)** The subagent `.claude/agents/store-investigator.md` runs investigations A1–A6: it downloads and analyzes the page outside the main context and returns only the conclusion and fixture paths (never raw HTML). It does not bypass blocks and does not edit `src/` or the spec.
- **REQ-DX-014 (MUST)** RTK (`oss` edition, Apache-2.0) filters the agent's Bash command output through a `PreToolUse` hook in `.claude/settings.json` (`rtk hook claude`; no-op if the binary is missing). Per-user install: `RTK_EDITION=oss sh install.sh` (verifies SHA-256); never `rtk init -g` nor the proxy daemon. RTK rewrites `git`, `tsc`, `biome` and `vitest`, but **cannot see inside `package.json` scripts**: therefore `pnpm check` and `pnpm test` must keep their own output lean (`dot` reporter / failures only, no banners). Measure the effect with `rtk gain`.
- **REQ-DX-015 (MUST)** Context7 as a project MCP server in `.mcp.json` (`https://mcp.context7.com/mcp`, no key; an optional key from the Context7 dashboard raises limits). Use is restricted to library APIs (NestJS, Drizzle, libSQL, Vitest, Biome, zod): pass the library ID and version. Never send secrets or project content in queries.
- **REQ-DX-016 (SHOULD)** Agent replies use Claude Code's `Concise` output style (`outputStyle` in `.claude/settings.local.json`, personal preference, git-ignored). A third-party plugin to shorten replies is added only if, after measuring with `/usage`, the native style is not enough.

### 15.2 Build order (walking skeleton before real adapters)

1. Scaffold + `pnpm check` + lefthook + `.claude/settings.json` + `req`/`req:check` (DX-001 to DX-008).
2. Config (zod) + `DbModule` + migrations + `migrate` (CFG, DB).
3. `Clock`, `FakeAdapter`, `FakeNotifier`, `CycleService` with lock and scheduler (RUN, CYC, SCH), with the 8.2 integration test.
4. Pure evaluators and `AlertsService` (ALR).
5. Notifiers and channel parser (NOT).
6. API and auth (API).
7. M1 adapters, `kabum` and `mercadolivre`, with investigation A6/A1 and fixtures (ADP, TST-010 to TST-013).
8. `slim` `Dockerfile`, compose, and size and cold-start measurement (CNT).

Each step ends with `pnpm check` green and `pnpm req:check` reviewed.
